一、现状总结与转变方向

当前 Demo 架构

  • 形式：Claude Artifact (自包含 HTML + browser localStorage)
  • 存储：单设备浏览器本地存储
  • 功能：完整的 UI 与客户端逻辑（STR discovery, gel 校准, dashboard）
  • 缺陷：跨设备不同步、无用户账号、无数据备份

商业化必需的转变

✓ 从单机应用 → 多用户云平台
  • 浏览器前端 + 服务器后端分离
  • 中央数据库存储（PostgreSQL）
  • 用户认证与访问控制（OAuth2 + JWT）
  • 实时多设备同步（WebSocket）
  • 云文件存储（S3 或 OSS）

二、技术架构方案

推荐方案：标准 Web 应用 + RESTful API

2.1 前端技术栈

Frontend: React 18+ (或 Vue 3) ├─ TanStack Query (React Query) - 服务器状态管理 ├─ Zustand/Redux - UI 状态管理 ├─ WebSocket client - 实时同步 ├─ TypeScript - 类型安全 └─ Ant Design / Material-UI - UI 组件库

2.2 后端技术栈

推荐：FastAPI (Python)

✓ 原生 async/await
✓ 自动 API 文档
✓ BioPython 集成好
✓ 部署简单

备选：Node.js/Express

✓ TypeScript 全栈
✓ WebSocket 性能好
✓ 大量生态库
✓ 开发速度快

2.3 核心基础设施

组件 推荐选择 说明
数据库 PostgreSQL 15+ 支持 JSONB、强大的查询能力
ORM SQLAlchemy (Python) 或 Prisma (Node.js) 数据库操作抽象
任务队列 Celery + Redis 后台任务（Primer3 设计、BLAST）
文件存储 AWS S3 或阿里云 OSS Gel 图、CE 数据、导出文件
缓存 Redis 会话、UCSC 基因数据缓存

三、用户账号与认证方案

3.1 认证流程（OAuth 2.0 + JWT）

登录流程：
  1. 用户输入邮箱/密码 → 后端验证
  2. 生成 JWT access token（15分钟过期）
  3. 返回 refresh token（7天，存在 httpOnly cookie）
  4. 前端每次请求在 Authorization header 中带 access token
  5. Token 过期时自动用 refresh token 获取新的

3.2 多设备同步方案

设备 A 上传新数据 ↓ 服务器保存 + 记录版本号 ↓ WebSocket 广播给用户其他在线设备 ↓ 设备 B/C 实时刷新或用户手动同步

3.3 离线支持

  • 前端缓存最后同步的数据（IndexedDB ~50MB）
  • 离线时继续可用（只读或排队写操作）
  • 恢复网络后自动同步（conflict resolution：server-wins）

四、部署选项与成本

选项 A：自托管（推荐用于起步）

✓ 优点
  • 完全数据所有权（对实验室重要）
  • 无月费（只需服务器成本）
  • 源码可见，完全定制
服务器配置
  • VPS：2核 2GB RAM（阿里云/腾讯云）
  • 成本：¥100-200/月
  • 部署：Docker Compose

选项 B：Supabase（最快起步）

推荐用于第一个 3-6 个月
  • Supabase：PostgreSQL + Auth + Storage - ¥150-300/月
  • 前端：Vercel 部署 - 免费或 ¥10/月
  • 总成本：约 ¥150-300/月
  • 优点：无需运维，快速上线

选项 C：AWS/阿里云

AWS
  • API Gateway + Lambda
  • RDS PostgreSQL
  • S3 文件存储
  • 成本：¥500-2000/月
阿里云
  • 函数计算 (Serverless)
  • RDS PostgreSQL
  • OSS 文件存储
  • 成本：¥200-1000/月
  • 优势：中国大陆访问速度好

推荐分阶段方案

阶段 1（起步，0-3 个月）

Supabase + Vercel
成本：¥150-300/月
关注：功能完整性

阶段 2（验证商业模式，3-12 个月）

迁移到自托管或阿里云
成本：¥500-2000/月
关注：可靠性、备份、监控

阶段 3（成熟产品，1 年+）

Kubernetes 或完全托管
成本：¥2000+/月
关注：扩展性、全球部署

五、商业模式选项

模式 1：SaaS 订阅（推荐）

层级 特性 定价
免费版 1 个项目, 100 STR 候选, 10 个 gel 图/月 ¥0
Pro 版 无限项目, 1000 STR, 100 gel 图/月, 优先支持 ¥99/月 或 ¥900/年
企业版 团队协作(5人), 无上限, 自定义导出, 技术支持 ¥2000+/年 或询价

模式 2：一次性授权

  • 单个实验室许可证：¥5000-10000（永久使用）
  • 支持 3 个用户账号
  • 包含 1 年免费更新

模式 3：订阅 + 服务（混合）

  • 平台使用费：¥200-500/月
  • 技术支持：¥1000/小时
  • 定制开发（新基因）：¥5000/次

六、数据安全与合规

6.1 数据加密与访问控制

传输层： HTTPS/TLS 1.3
存储层： 数据库字段级加密（PCR 结果等关键字段）
备份： 加密备份存储
访问控制： 用户只能看自己的项目，细粒度权限管理
审计日志： 谁在什么时间改了什么

6.2 自动备份与灾难恢复

  • 每日增量备份到云存储
  • 保留 30 天历史
  • RTO（恢复时间）：4 小时
  • RPO（数据丢失量）：<1 小时
  • 用户可手动导出为 JSON/Excel

6.3 法规合规

  • GDPR（欧盟）：支持数据导出、删除
  • 中国数据法：可选本地存储
  • 生物安全：实验室数据不转移第三方

八、关键决策清单

  • 技术栈：选择 FastAPI (Python) 还是 Node.js/Express？
  • 部署方式：自托管、Supabase 还是阿里云？
  • 商业模式：SaaS 订阅、一次性授权还是混合？
  • 开源策略：完全闭源还是部分开源？
  • 团队规划：是否需要招聘后端/前端工程师？
  • MVP 范围：先上线基础功能，后迭代新功能？
  • 首发目标市场：国内、国际还是兼顾？

推荐的起步方案

技术： FastAPI + React + PostgreSQL + Supabase
部署： Supabase (前 6 个月) → 自托管/阿里云 (成熟后)
商业： SaaS 订阅模式 (Free/Pro/Enterprise)
时间： 3 个月 MVP，6 个月正式上线
成本： 第一年约 ¥200K-300K (包含人力)
