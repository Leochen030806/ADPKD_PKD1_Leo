1 背景与整体框架

1.1 什么是 PGT-M？

植入前遗传学检测（Preimplantation Genetic Testing for Monogenic disorders）

  • 针对单基因遗传病（如 PKD1 — 常染色体显性多囊肾病）
  • 在胚胎植入前，通过 STR 标记进行基因诊断
  • 确保出生的孩子不携带致病等位基因

1.2 核心技术：STR 标记

短串联重复（Short Tandem Repeat）：DNA 指纹识别的基础

  • PKD1 关联的 STR 标记：32 个
  • 每个 STR 有多个等位基因（allele）
  • 通过 CE（毛细管电泳）检测基因型

1.3 当前痛点

  • 🔴 STR 发掘、Primer 设计 → 纯手工，耗时 2-3 周
  • 🔴 CE 数据处理 → 需要人工标注基因型，易出错
  • 🔴 质量控制 → 缺乏系统性检查，无法复用知识

1.4 平台的使命

构建一个端到端的自动化工作流，通过机器学习驱动的自动化，将 2-3 周的工作压缩到 1 周以内，准确率 >99.5%。

2 干实验流程：STR 发掘与 Primer 设计
图 1：干实验流程全景

2.1 基因组扫描与 STR 定位

  • 在 PKD1 基因周围扫描已知的 STR 位点
  • PKD1 相关标记库：已有 32 个候选 STR

2.2 PrimerAST 特征评估（关键）

24 维特征用于评估 primer 质量：

  • 热学特性：Tm、ΔΔG、GC%
  • 特异性：与目标 STR 的互补性评分
  • 相互作用：primer 间的二聚体形成倾向
  • 背景复杂度：在全基因组中的重复序列匹配
  • PCR 效率预测：基于序列特征的放大效率

2.3 候选池排序与精选

  • 对每个 STR 位点生成 100~500 个候选 primer
  • 使用 24 维特征进行排序（目前：人工打分）
  • 选出 Top 3~5 个候选进入湿实验验证
🎯 关键发现点： 这 24 维特征与最终的"好 primer"之间是否有明确的相关性？能否通过机器学习找到最优的特征组合，而不是人工打分？
3 湿实验流程与 CE 结果分类
图 2：湿实验工作流与 CE 分类

3.1 Tm 优化

  • 梯度 PCR：同时进行 8~12 个不同温度的反应
  • 目标：找到最高特异性 + 最高效率的退火温度

3.2 Gel 电泳验证

  • 检查 PCR 产物大小（预期范围 ~100-500 bp）
  • 检查纯度（单条带 vs 多条带表示特异性问题）

3.3 单重 CE（单个 STR）

  • 逐个 STR 进行 CE 检测（可选，但推荐进行基准测试）
  • 评估：峰值分辨率、背景噪声、等位基因覆盖范围

3.4 多重 CE（全 STR 面板）

  • 同时检测 32 个 STR 标记（通过不同荧光标签区分）
  • 在真实的 PGT-M 工作流中使用（16 个 Coriell 参考样本）

3.5 CE 结果的 6 分类（关键）

分类 描述 CE 特征 医学意义
0: 纯合 单等位基因 1 个峰，高度集中 无杂合信号
1: 杂合平衡 两个等位基因 2 个峰，高度 ~1:1 正常杂合子
2: 杂合不平衡 两个等位基因 2 个峰，高度 1:2 可能有突变
3: 多等位 ≥3 个等位基因 ≥3 个峰 污染或罕见多态性
4: 无信号 PCR/CE 失败 无峰或极弱信号 需要重做
5: 异常 其他异常模式 不规则峰型 需人工审核
🎯 关键问题： 如何自动识别这 6 个分类？需要什么样的特征和模型架构？
4 数据对应与平台数据集构想
图 3：从实验流程到训练数据集的映射

4.1 数据对应的三个关键维度

  • Marker 维度：32 个 STR 标记
  • Design 版本维度：每个 marker 有 2-3 个 primer 版本（迭代优化）
  • 样本维度：16 个 Coriell 参考样本（标准化数据集）

4.2 一条训练记录的组成

1 条 = 1 个 marker + 1 个 design 版本 + 16 个样本的聚合

  • 48 个特征列：CE 峰值（24）+ 信号质量（12）+ Primer 特征（12）
  • 1 个标签列：基因型分类（0-5）
  • 数据来源：16 个样本在该 marker-design 组合上的 CE 数据（统计聚合）
🎯 平台构想的核心： 建立一个系统，自动采集、对齐和聚合每个实验步骤的数据，形成结构化的训练数据集。避免重复实验、确保数据一致性、支持版本控制。
5 机器学习方案与咨询重点
图 4：ML 管道与数据流

5.1 核心问题：为什么选 XGBoost？

总结：小数据集 + 医学诊断 = XGBoost 最优

  • ✓ 数据集只有 ~96 条，深度学习容易过拟合
  • ✓ 特征重要性可视化，医学可解释性强（关键！）
  • ✓ 特征交互（如"峰高比 × 峰数"）自动学习，无需人工组织
  • ✓ 已有医学应用案例，相对保险

🎯 对博士的咨询问题 1：算法选择

  • 你是否同意 XGBoost 是最佳选择？有没有其他算法（随机森林、SVM、LightGBM）值得对比？
  • 如果未来数据扩展到 1000+ 条，是否应该考虑神经网络或集成多个模型？
  • 对于医学诊断，可解释性和准确性哪个更重要？

5.2 数据采集策略

  • 分层维度：按 marker × design 版本 × sample 组织
  • 聚合方式：16 个样本 → 1 条记录（统计聚合特征）
  • 数据独立性：确保同一记录来自同一 CE run 和 worksheet（避免技术差异混淆）
  • 标签标注：手工基准（目前）+ 自动验证（诊断脚本）

🎯 对博士的咨询问题 2：数据收集

  • 平台应该怎样自动采集这些数据，确保数据一致性和可追溯性？
  • 16 个样本聚合成 1 条是否合理？有没有更好的聚合方法？
  • 如何在平台级别实现数据版本控制和实验可重复性？
  • 每条记录需要记录哪些元数据（实验日期、操作者、仪器ID等），用于未来的模型监控和漂移检测？

5.3 数据标注方式

  • 初期标注：由生物学家手工标注 CE 结果为 0-5 分类
  • 质量控制：多人标注同一样本，计算 inter-rater 一致性
  • 自动验证：诊断脚本检查标注是否一致（跨重复、跨批次）
  • 主动学习：模型不确定的样本优先标注（可选）

🎯 对博士的咨询问题 3：数据标注

  • 标注成本能否接受？多少时间可以标注 96 条记录？
  • 标注者之间的一致性（kappa）应该达到什么水平才能用于训练？
  • 能否通过半监督或弱监督学习减少标注工作量？

5.4 训练集 / 测试集划分

  • 不能简单的 80/20 分割：数据量太小，方差大
  • 应该用分层 k-fold 交叉验证：5-fold 或 leave-one-marker-out
  • 重点：避免数据泄漏
    • 不能把同一 marker 的不同版本（v1, v2, v3）分到训练/测试集
    • 不能把同一 marker 的不同样本分到训练/测试集
  • 最终模型评估：找一个完全没见过的 marker（新样本、新版本），测试模型的泛化能力

🎯 对博士的咨询问题 4：数据划分

  • 给定 ~96 条数据，最合理的交叉验证方案是什么？
  • 如何在 marker-level 或 sample-level 进行分层，确保训练/测试集的独立性？
  • 是否应该保留最后 1-2 个 marker 的全部数据作为"最终测试集"（模拟真实部署）？

5.5 训练成本与流程估计

  • 数据准备：1-2 周（收集、清洗、标注 ~96 条）
  • 特征提取：3-5 天（从 CE 原始数据提取 48 维特征）
  • 模型训练与调参：2-3 周（超参数搜索、交叉验证）
  • 医学验证：2-4 周（与手工报告对比、差异分析）
  • 平台集成：2-3 周（集成到 web 应用、实时推理）
  • 总时间：~2-3 个月

🎯 对博士的咨询问题 5：成本与流程

  • 上述时间估计是否现实？瓶颈在哪里？
  • 能否并行进行某些步骤（如特征提取和模型设计）？
  • 医学验证阶段应该做什么测试确保模型可以投入实际应用？
  • 如何设计流程确保可重现性和可审计性（关键：医学应用）？
