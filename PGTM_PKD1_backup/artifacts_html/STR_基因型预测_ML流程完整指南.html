1问题定义与背景

核心任务

基于 CE（毛细管电泳）原始数据，自动预测 STR 标记的基因型。这是 PGT-M（植入前遗传学检测）工作流中的关键自动化环节。

为什么需要机器学习？

  • 准确性：医学诊断要求 >99.5% 准确率，错分类风险无法接受
  • 效率：手工标注耗时，自动化可加速流程
  • 一致性：减少人为判断差异，保证结果可重复

医学背景

STR（短串联重复）标记是 DNA 指纹识别的基础。每个 STR 位点可有多个等位基因（allele），现在已有 PKD1 基因相关的 32 个 STR 标记。

关键指标： 金标准验证数据是 16 个 Coriell 参考样本，在 marker 2517（STR 3）上的表现为：
• 15 分型 × 16 样本 = 16 个独立的等位基因观察
• HET 73.3%（杂合度）
• 6 个等位基因（423–435 bp）
• 与手工报告完全一致，最大校正误差 0.074 bp

当前工作流缺陷

  1. CE 数据需要人工标注（标记孔位、基因型）
  2. 标注耗时且易出错（E-H 孔文件名混淆案例）
  3. 难以质量控制（缺乏系统性检查）
  4. 无法知识复用（每次重新开始）

2数据采集与预处理

数据来源

PGT-M Panel Studio 平台中的 CE 运行记录。数据存储在全局对象中：

// 三层身份架构 LOCI[gene] = [{id, name, ...}] // 基因及其 STR 位点 DESIGNS[locusId] = [{id, version, ...}] // 每个位点的引物设计版本 EVENTS = eventsFor(locusId, designId) // CE 运行事件

数据采集流程

第1步：收集原始数据

从 EVENTS 中提取每个 marker-design 组合的 CE 原始数据

第2步：样本身份验证

确保 16 个 Coriell 样本完整、无混淆（验证 run/worksheet 一致性）

第3步：质量控制检查

运行诊断脚本（checkRunIntegrity / verifyCoriellPanel / verifyDesignVersionConsistency）

第4步：修复缺陷

修正发现的数据问题（缺失样本、版本不一致等）

第5步：数据聚合

16 个样本 → 1 条训练记录（统计聚合基因型频率）

预处理步骤

① 数据清洁

  • 移除缺失值或异常值（signal loss 的孔）
  • 检查样本名格式（应为 NA + 5 位数字）
  • 验证峰值信息完整性（peak 高度、面积、大小）

② 归一化

  • 峰值高度：除以样品内最高峰（0–1 范围）
  • 峰值面积：相对比例（总和 = 1）
  • 大小：使用内标准化（bp 单位）

③ 缺失值处理

  • Signal loss 孔：标记为 0（无检出）
  • 其他缺失值：使用该 marker 的中位数填充
⚠️ 重要：数据独立性
16 个样本必须来自同一个 CE run和同一个 worksheet，避免不同批次的技术差异混淆。

3特征工程

特征来源

从每个 CE 孔位（12-well plate 每孔一个样本）的峰值信息中提取。

特征定义（48 列）

特征类别 数量 具体内容 提取方法
峰值高度 6 前 6 个最高峰的高度（归一化） height / max_height
峰值面积 6 前 6 个最高峰的面积（相对） area / sum_area
峰值大小 6 前 6 个最高峰的大小（bp） 绝对 bp 单位
峰值数 1 总峰数 count(peaks)
峰值宽度 6 前 6 个最高峰的宽度 base_width (bp)
峰值间距 5 相邻峰之间的大小差 peak[i+1] - peak[i]
平衡度 1 最高峰与次高峰的比值 height1 / height2
噪声指标 1 信噪比（signal to noise ratio） mean(peak) / std(baseline)
信号质量 1 峰值回收率 sum(peak_area) / total_dye
标签特征 6 标签颜色/荧光强度 分色道信息

特征重要性预期

基于医学知识的初步排名：

  1. 峰值大小（bp）：最重要，直接对应等位基因长度
  2. 峰值高度比例：区分杂合/纯合，判断等位基因比例
  3. 峰值数量：一眼看出是杂合（2个等位）还是纯合（1个等位）
  4. 峰值宽度：反映 PCR 产物多态性和检出能力
  5. 信噪比：区分真峰和噪声

特征准备代码框架

function extractFeatures(ceEvent) { // ceEvent.data.rows = [{peak_height, peak_area, peak_size, peak_width, ...}] const peaks = ceEvent.data.rows .filter(p => p.peak_height > noise_threshold) .sort((a, b) => b.peak_height - a.peak_height); const features = {}; // Peak heights (6) for (let i = 0; i < 6; i++) { features[`height_${i}`] = peaks[i]?.peak_height / max_height || 0; } // Peak sizes (6) for (let i = 0; i < 6; i++) { features[`size_${i}`] = peaks[i]?.peak_size || 0; } // ... 其他特征 return features; }

4模型选择

为什么选择 XGBoost？

✓ 小数据集表现最佳

~96 个训练样本，XGBoost 比深度学习更稳定，过拟合风险低。

✓ 可解释性强

医学诊断必须说得清楚"为什么"，XGBoost 特征重要性图表直观。

✓ 医学级别性能

特征交互自动捕捉（峰值高度 × 大小），无需人工设计。

✓ 计算高效

秒级推理，适合实时 CE 数据处理。

模型架构

多分类 XGBoost，输出 6 个类别：

类别 0: 无信号（signal loss） 类别 1: 单等位基因（homozygous） 类别 2: 两个等位基因，比例 ~1:1（heterozygous balanced） 类别 3: 两个等位基因，比例 1:2（heterozygous imbalanced） 类别 4: 三个及以上等位基因（polyclonal 或污染？） 类别 5: 异常峰型（需人工审核）

超参数初始值

参数 初始值 说明
max_depth 4-6 小数据集，浅树防过拟合
n_estimators 100-200 树数量，可通过早停自动调整
learning_rate 0.05-0.1 学习率，低值更稳定
min_child_weight 5 最小样本权重，防过拟合
subsample 0.8 样本采样率
colsample_bytree 0.8 特征采样率
✓ 对标准： 金标准数据集（PKD1_order_list_0610.xlsx）上达到 99.5%+ 准确率。

5训练与验证

数据集划分

分层交叉验证（stratified k-fold），防止数据泄漏：

  • 不能按样本分：16 个 Coriell 样本是同一批，做不了测试集
  • 应该按 marker-design 分：每次选 2-3 个不同的 marker × version 组合做测试
  • 交叉验证：5-fold 或 leave-one-marker-out
🚨 数据泄漏风险： 同一 marker 的不同版本（v1, v2, v3）不能混在训练/测试集，因为引物序列相似，模型可能"记住"而非"学习"。

训练流程

准备阶段

数据聚合（16 样本 → 1 记录）、特征提取、归一化

初始训练

使用默认超参数快速验证

超参数优化

Bayesian 搜索或 GridSearch（max_depth, learning_rate）

交叉验证

5-fold stratified k-fold，记录每折的 metrics

最终模型

在全数据集上重新训练（保存为 model.pkl）

验证指标

① 整体性能

  • 准确率（Accuracy）：(TP+TN) / Total，目标 >99%
  • 精确率（Precision）：TP / (TP+FP)，每个类别分别计算
  • 召回率（Recall）：TP / (TP+FN)，防止漏检
  • F1 分数：调和平均，综合评分

② 医学特定指标

  • 基因型一致率：预测基因型与手工报告的一致性（目标 100%）
  • 等位基因推断准确率：每个等位基因的 bp 大小偏差 < 0.1 bp
  • 杂合度错误率：错分杂合/纯合的概率
类别 样本数 精确率 召回率 F1 分数 医学风险
0: 无信号 ~3 >98% >95% >0.96 低（明显差异）
1: 纯合 ~20 >99.5% >99% >0.995 中（遗漏另一等位）
2: 杂合平衡 ~30 >99.5% >99% >0.995 高（遗传咨询关键）
3: 杂合不平衡 ~25 >99% >98% >0.985 高（可能有突变）
4: 多等位 ~5 >98% >90% >0.94 中（需人工审核）
5: 异常 ~13 >95% >90% >0.92 低（转移给审核）

训练代码框架

  • 部署 Flask/FastAPI 服务
  • 适合需要实时监控/日志的情况
  • 可配置版本控制和 A/B 测试

集成点

// 平台集成伪代码 function autoLabelCEResult(ceEvent) { // 1. 特征提取 const features = extractFeatures(ceEvent); // 2. 预测 const prediction = model.predict(features); // 返回类别 0-5 const confidence = model.predict_proba(features); // 3. 生成标注 const label = mapPredictionToLabel(prediction); ceEvent.data.autoLabel = { genotype: label.genotype, alleles: label.alleles, confidence: confidence[prediction], timestamp: new Date(), modelVersion: '1.0' }; // 4. 保存到平台 addEvent({ type: 'genotypePrediction', data: ceEvent.data.autoLabel, ... }); // 5. 人工审核 if (confidence[prediction] < 0.95) { flagForManualReview(ceEvent, 'Low confidence'); } return ceEvent; }

质量控制

  • 置信度阈值：< 0.95 的预测需要人工审核
  • 类别特定警告：类别 4（多等位）和 5（异常）自动标记为待审核
  • 模型监控：定期验证预测与手工标注的一致性
  • 版本控制：记录每个预测使用的模型版本
✓ 目标： 90% 的 CE 结果无需人工审核，自动通过；10% 标记为"需要审核"。

7诊断与维护

数据质量诊断

在开始训练前，必须运行诊断脚本检查平台数据完整性：

// 在浏览器 console 中运行 diagnosticReport()

三个核心检查：

  1. checkRunIntegrity() — 16 个样本是否来自同一 run/worksheet
  2. verifyCoriellPanel() — 16 个 Coriell 样本是否完整正确
  3. verifyDesignVersionConsistency() — CE 数据的引物版本是否一致

常见问题与修复

问题 1：样本数不足（< 14 个）

原因： CE 运行失败或样本缺失
修复： 检查实验室记录，补充缺失样本，重新运行 CE

问题 2：样本混淆（E-H 孔文件名错位）

原因： CE 数据导入时孔位标签错配
修复： 手工核实原始 CE 文件，调整孔位映射

问题 3：版本不一致

原因： 引物更新但 CE 数据未重新导入
修复： 使用新版引物重新运行 CE，导入新数据

模型监控

① 性能漂移检测

  • 每月检查最近 100 个预测的准确率
  • 如果准确率下降 > 2%，触发重新训练
  • 记录每次漂移的原因（新样本类型、CE 机器升级等）

② 特征监控

  • 检查新数据的特征分布是否与训练数据一致
  • 如果出现显著偏移，可能需要重新训练

③ 预测置信度

  • 记录每个预测的置信度分布
  • 低置信度预测的错误率是否高于平均值
