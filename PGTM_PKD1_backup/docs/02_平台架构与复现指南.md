# 02 · 平台架构与复现指南

平台由三层组成。只要备齐这三层，就能在另一台电脑或另一个账号上把整套流程重新跑起来。

```
┌──────────────────────────────────────────────────────────────┐
│ ① 前端：PGT-M Panel Studio（单页 HTML，platform/panel_studio/）│
│    干实验区（STR 发现）· 湿实验区（胶图模块）· 总体看板（CE 图谱）│
│        │ 通过 MCP 调用 str_run_list / start / status / data    │
├────────┼─────────────────────────────────────────────────────┤
│ ② 后端：本地 MCP 服务 "pgtm" + trexplorer_str.py v2.1           │
│    （位于 Leo 实验室电脑 Desktop\PKD1cloude发现\pgtm平台\）       │
│    ⚠ 本备份中没有这部分源码，见下面第 ② 节                       │
├──────────────────────────────────────────────────────────────┤
│ ③ 流程 skill（skills/，可独立运行的 Python/Node 脚本 + SOP）     │
│    panel-design → panel-order → gel-titration → ce-report-slides│
│    + str-csv-allele-report                                     │
└──────────────────────────────────────────────────────────────┘
```

---

## ① 前端 Panel Studio

**文件**：`platform/panel_studio/`

| 文件 | 内容 |
|---|---|
| `index.html` | 完整的单页应用（约 724 KB，自包含）；只从 cdnjs 加载一个外部库 `exceljs@4.4.0` |
| `runs/index.json`、`runs/PKD1_*.json`、`runs/PKD2_*.json` | 两次真实的 STR 挖掘结果（schema `str-page-data/1`），含参数、漏斗、节段重复区、2812 个位点和侧翼序列 |
| `ce/<marker>.json` | 13 个 marker 的 simplex CE 结果（16 个样本的基因型，内嵌图谱） |
| `ucsc/chr16_simpleRepeat_snapshot.json` | UCSC simpleRepeat 的离线快照（chr16:588k–3.64M，period 1–6，**缺 2.2–2.8 Mb 这一段**） |

**本地打开**（不需要账号）：

```bash
cd PGTM_PKD1_backup/platform/panel_studio
```

```bash
python3 -m http.server 8000
```

然后用浏览器打开 `http://localhost:8000/`。必须通过 HTTP 访问，因为页面要 `fetch` 同目录下的 `runs/`、`ce/`、`ucsc/` 文件；直接双击打开 file:// 地址会读不到这些数据。

**在另一个 Claude 账号里重新发布**（得到可分享的链接）：在 Claude Code 里对 Claude 说「把 `platform/panel_studio/` 发布为 artifact，包括 `runs/`、`ce/`、`ucsc/` 下的全部文件，声明 `db`、`downloads` 能力，以及 MCP 服务 `pgtm` 的 4 个工具」。

**两个已知限制**（artifact 沙箱的限制，自建服务器上部署时没有）：
1. 发布后的页面不能向外部网站发请求，所以 UCSC 数据读的是内置快照。
2. 状态保存在浏览器的 localStorage 里，换一台电脑不会跟过去。模板库提供 JSON 导出/导入来弥补。

**前端调用后端的接口约定**（来自 `index.html`）：

| MCP 工具 | 参数 | 用途 |
|---|---|---|
| `str_run_list` | — | 列出已有的 run |
| `str_run_start` | `{gene, flank_kb}` | 新建一次 STR 挖掘，返回 job id |
| `str_run_status` | `{run_id}` | 查询进度 |
| `str_run_data` | `{run_id, offset, limit}` | 分块读取结果 JSON（schema `str-page-data/1`） |

没有后端时，页面仍然可以浏览 `runs/` 里已经有的两次结果，只是不能新建 run。

## ② 后端（⚠ 需要从原电脑补齐）

`runs/index.json` 显示，后端脚本是 **`trexplorer_str.py` 2.1 版（2026-10-21）**，sha256 以 `c6f2bffe…` 开头，运行目录为：

```
C:\Users\e1638543\Desktop\PKD1cloude发现\pgtm平台\
   ├── trexplorer_str.py         (STR 挖掘 + A/B/C 分级)
   ├── <MCP 服务入口>             (提供 str_run_* 这 4 个工具)
   └── runs\<GENE>_<时间戳>\04_交付文件\*.xlsx / *.docx
```

**这部分代码只保存在那台 Windows 电脑上**，云端的 Claude 读不到。补齐的方法：
1. 把整个 `pgtm平台` 文件夹（只需代码和配置，`runs/` 里的大文件可以不要）复制到本仓库的 `platform/backend/` 目录，然后提交。
2. 或者在那台电脑上打开 Claude Code，说「把 Desktop\PKD1cloude发现\pgtm平台 的源码加入 ADPKD_PKD1_Leo 仓库的 PGTM_PKD1_backup/platform/backend 并推送」。

补齐之后，在新电脑上的配置步骤是：`pip install` 依赖 → 在 Claude 桌面应用或 Claude Code 的 MCP 设置里添加名为 `pgtm` 的本地服务器，指向服务入口脚本 → 打开 Panel Studio。

后端的算法规则（阈值和漏斗）已经完整记录在 01 号文档第 8 节和 `runs/*.json` 的 `run.thresholds` 字段里。即使源码丢了，也可以按这些规则重写。

## ③ 流程 skill（核心可复现部分）

| Skill | 作用 | 运行环境 |
|---|---|---|
| `pgtm-str-panel-design` | 从基因名到候选 STR、颜色 × 长度网格、Primer3 参数 | Python 3（只用标准库） |
| `pgtm-str-panel-order` | 保留/重设计决策 → 加尾 → QC → **下单表.xlsx** | Python 3 + `openpyxl` |
| `pgtm-gel-titration-report` | 胶图照片 → 一页标准报告 PPT | Node.js + `pptxgenjs` |
| `pgtm-ce-report-slides` | GeneMapper 截图 + CE 汇总表 → 每个 marker 两页的竖版 PPT | Python（`openpyxl python-pptx pillow`）或 Node |
| `str-csv-allele-report` | SeqStudio CSV 文件 → LIZ-500 校准 → 等位基因判读 | 只有 SOP 文档，没有脚本 |

### 安装依赖

```bash
pip install openpyxl python-pptx pillow
```

```bash
npm install pptxgenjs xlsx sharp tesseract.js
```

（实验室电脑受域管理、装不了 Node 时，只用 Python 版即可，见 `skills/pgtm-ce-report-slides/references/running_on_windows.md`。）

### 已验证可运行（2026-11-19，Linux + Python 3）

```bash
cd PGTM_PKD1_backup/skills
```

```bash
python3 pgtm-str-panel-order/scripts/panel_qc.py pgtm-str-panel-order/examples/pkd1_records.json
```

```bash
python3 pgtm-str-panel-order/scripts/build_order_list.py pgtm-str-panel-order/examples/pkd1_records.json -o 下单表.xlsx
```

预期结果：QC 只报告一项（2517 PET 429 bp 超出窗口，这是有意保留的长片段备份）；4 个标记需要单重验证（2038/2769/1202/1725）；生成 24 条 oligo、12 个 marker 的下单表。

### 把 skill 装进另一个 Claude 账号

skill 装好以后，Claude 会在对话里自动调用它们，例如说「接下来是 2517 的」并附上截图，就会触发 CE 报告流程。

- **Claude Code（任意电脑）**：运行 `tools/install_skills.sh`（macOS/Linux）或 `tools/install_skills.ps1`（Windows），脚本会把 5 个 skill 复制到 `~/.claude/skills/`。
- **claude.ai 网页 / 桌面应用**：Settings → Capabilities → Skills → Upload skill，把每个 skill 文件夹分别打包成 zip 上传（`tools/install_skills.sh --zip` 会在 `dist/` 目录生成这些 zip）。

## 推荐给同事的上手顺序

1. 读 `docs/01_生物医学背景与项目知识.md`（约 15 分钟）。
2. 按 ① 在本地打开 Panel Studio，浏览 PKD1 run 和 CE 看板。
3. 跑一遍 ③ 的 QC 和下单表命令，对照 01 号文档第 5 节的表格。
4. 安装 skill，用 PKD2 实际走一遍 design → order 流程。这也是平台待开发清单里「第一次模板复用验证」那一项。
